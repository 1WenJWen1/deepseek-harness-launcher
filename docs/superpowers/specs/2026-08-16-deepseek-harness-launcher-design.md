# DeepSeek Harness Windows 启动器设计

## 目标

为本机的 `@deepseek-ai/dsh web` 提供接近普通 Windows 应用的使用方式。用户只需双击桌面的 `DeepSeek Harness` 图标；启动期间不显示终端窗口，关闭应用窗口时一并停止本次启动的本地 DSH 服务。

## 范围

- 应用名称为 `DeepSeek Harness`。
- 桌面只创建一个启动图标，不额外创建停止图标。
- 图标采用 DeepSeek 风格的蓝色鲸鱼视觉，并明确属于本地启动器，不声明官方签名。
- 通过 Microsoft Edge 的应用模式显示 `http://127.0.0.1:3080`。
- 后台运行 `npx @deepseek-ai/dsh web`，不显示终端窗口。
- 用户关闭由启动器打开的 Edge 应用窗口后，启动器终止其启动的 DSH 子进程。

不包括：修改 DeepSeek Harness 源码、制作 Electron 安装包、注册 Windows 服务、自动开机启动，以及发布或上传安装包。

## 组成

1. **隐藏启动脚本**：负责环境检查、启动 DSH、等待端口、启动 Edge 和清理子进程。
2. **无窗口入口**：从桌面快捷方式调用隐藏启动脚本，避免出现黑色终端窗口。
3. **桌面快捷方式**：显示 `DeepSeek Harness` 名称和自定义 `.ico` 图标。
4. **应用数据目录**：为 Edge 应用窗口使用独立、固定的用户数据目录，便于可靠跟踪窗口进程，不干扰用户日常 Edge 配置。

## 运行流程

1. 检查 Node.js、npx 和 Microsoft Edge 是否可用。
2. 检查 TCP 端口 `3080`。若已被无法识别的程序占用，则停止启动并显示中文错误，不结束未知进程。
3. 隐藏启动 `npx @deepseek-ai/dsh web`，记录所创建的进程。
4. 轮询 `127.0.0.1:3080`，直到页面可访问或达到启动超时。
5. 使用 Edge `--app=http://127.0.0.1:3080` 打开独立窗口，并等待该应用窗口进程退出。
6. 窗口退出后，只终止第 3 步创建的 DSH 进程树；不按名称批量结束其他 Node 或 Edge 进程。

## 异常处理

- 缺少 Node.js、npx 或 Edge：显示中文提示并退出。
- DSH 启动超时：终止本次创建的进程并显示提示。
- 端口被其他程序占用：提示用户端口冲突，不自动杀死未知程序。
- Edge 无法启动：停止本次 DSH 服务并显示提示。
- 正常关闭窗口：清理 DSH 进程，使 `3080` 端口恢复为未监听状态。
- Edge 或系统异常退出：尽力执行清理；强制断电等情况无法保证清理逻辑运行。下次启动仍先检查端口，避免重复启动。

## 验证标准

- 桌面出现名称为 `DeepSeek Harness` 的单一快捷方式，并显示蓝色鲸鱼图标。
- 双击快捷方式后没有可见终端窗口。
- 独立应用窗口能够加载 DSH 页面。
- 关闭应用窗口后，本次启动的 DSH 进程退出，端口 `3080` 不再监听。
- 日常 Edge 窗口和其他 Node.js 进程不被关闭。
- 缺少依赖或端口冲突时出现可理解的中文错误提示。

## 已选方案与取舍

采用“Edge 应用窗口 + 隐藏启动器”，不采用 Electron 打包或 Windows 服务。该方案体积小、容易维护，也能满足点击窗口 `×` 后停止服务的交互。其本质仍由 Edge 和 Node.js 进程组成，并非带官方数字签名的原生 DeepSeek 可执行文件。
